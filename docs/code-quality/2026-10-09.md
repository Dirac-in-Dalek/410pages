# Archive consistency and code quality

The review identified four causes for seven reproducible storage failures,
plus responsibility, type-checking, and dependency maintenance work.

| Cause | Previous behavior | Change |
| --- | --- | --- |
| Incomplete reads | Response limits truncated archive lists and embedded notes/memberships. | Fetch every range with deterministic ordering and load child relations separately. |
| Concurrent requests and stale state | A delayed reorder could hide a newly created folder. Slow settings writes could overwrite newer preferences. | Reorder completion preserves current objects, and rollback restores order without removing newly added folders. Serialize settings writes with visible retry errors. |
| Partial mutations | A failed attachment could leave an empty folder; independent reorder writes could partially succeed. | Transactional create/attach and reorder RPCs share an owner lock. Creation retries reuse the same UUID. |
| Ambiguous API inputs and results | Clearing a page sent `undefined`. Updates affecting zero rows appeared successful. | Use `null` to clear pages and verify returned update rows. |
| Mixed responsibilities | The archive mutation hook, sidebar component, and PDF page mixed unrelated mutations, drag state, and rendering. | Split project, author folder, library record, and chapter mutations; move sidebar drag behavior to a logic hook; extract PDF canvas and metadata dialog components. |
| Weak checks and dependency drift | The Supabase client had no generated schema type; TypeScript strict checking and hook linting were absent. Development dependencies had known advisories. | Generate DB types, enable strict checking, enforce ESLint and hook dependencies in CI, and update affected development dependencies. Tailwind 4 retains the existing color, radius, shadow, blur, and ring values. |

## Database deployment

`supabase/migrations/20261009090000_atomic_project_mutations.sql` was applied to
`yyfapuwgvimbjsebfifb` on 2026-10-09 and recorded in
`supabase_migrations.schema_migrations` in the same transaction.
Both RPCs use `SECURITY INVOKER`, an empty search path, and the existing ownership
RLS policies. Production metadata confirms execution is granted to
`authenticated` and denied to `anon`. Existing user records were not changed.
Old clients remain compatible with this additive migration.

After changing the public schema, regenerate the types with Node.js 24 and a
management token supplied through the environment:

```sh
npm run db:types
npm exec tsc -- --noEmit
```

The generated file is `shared/api/database.types.ts`. Keep the nullable
`destination_book_id` correction in `databaseContract.ts`: PostgreSQL permits
NULL function arguments, but the type generator does not describe that fact.
Management tokens belong only in the development environment, never in Vite
variables or browser code.

## Validation

- 91 test files, 665 tests passed. New cases cover capped responses, real-form
  page clearing, zero-row updates, overlapping create/reorder, idempotent
  retries, settings write order/failure/retry/account changes, and SQL rollback.
- PGlite executes the migration against actual PostgreSQL with ownership RLS,
  authenticated/anonymous roles, and injected insertion/update failures.
- Strict typecheck, ESLint with zero warnings, and the production build passed.
- `npm audit` reports zero vulnerabilities, including development dependencies.
- Isolated Chromium fixtures passed mobile touch targets, title width, search,
  keyboard navigation, back/forward/reload, comments, and PDF lazy loading,
  failure, retry, and return navigation.
- Home geometry was compared at 375, 768, and 1440 pixels before/after the
  dependency update. Measured button sizes, font sizes, and document widths are
  identical, with no horizontal document overflow. External fonts were blocked
  in both comparison runs to keep the font environment consistent.

The settings queue orders writes within one mounted client. It does not resolve
concurrent changes from multiple devices. Paginated reads are ordered range
reads rather than a database snapshot. Tailwind 4's supported browser baseline
is Chrome 111+, Safari 16.4+, and Firefox 128+.
