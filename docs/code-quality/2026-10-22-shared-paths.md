# 공통 구현 재사용 정리

같은 규칙을 화면·저장·임시 상태에서 각각 구현하던 부분을 공유 경로로 이관했다.
아래 위치를 수정하면 해당 규칙을 사용하는 호출부가 함께 변경된다.

| 책임 | 정의 위치 | 이관한 호출부 |
| --- | --- | --- |
| 반응형 기준 | `shared/policy/responsive.js` | 앱 모드, 카드 줄 수, Tailwind screens, CSS의 모든 화면 폭 미디어 쿼리 |
| 읽기 기본값 | `shared/policy/readingDefaults.js` | 사용자 설정의 기본·최소·최대값과 빌드 시 생성되는 초기 CSS |
| 글자·색·그림자 | `index.css` | UI 컴포넌트에 직접 지정했던 고정 font-size와 RGB/hex 값. 역할별 토큰으로 대체 |
| 공통 버튼 | `shared/ui/Button.tsx` | 기존 공통 버튼 스타일을 사용하던 설정·아바타·사이드바·모바일 검색·PDF 재시도 |
| 페이지 해석 | `shared/logic/citationPage.ts` | API 저장, 임시 문장 생성/수정, 정렬 |
| 문장 수정 시 서식 | `shared/logic/citationEditing.ts` | 저장된 문장과 임시 문장 수정 |
| 입력 높이 | `shared/policy/textarea.ts`, `shared/ui/useAutosizeTextarea.ts` | 문장 입력, 카드의 문장/댓글 편집, 인라인 댓글 입력 |
| 저장소 접근 | `shared/lib/browserStorage.ts` | 인증 저장 정책, 설정, 패널 폭, PDF 세션, 문장/책 메모 초안, 프로필·책 메타데이터 캐시, 아바타 진단 |
| 모달 포커스 | `shared/ui/useModalFocus.ts` | 기존 삭제·아바타·탐색 대화상자와 별도 구현을 제거한 설정 패널 |

입력창의 빈 높이·최대 높이와 인라인 댓글의 자동 확장은 variant로 구분했다.
설정 패널의 처음 포커스 시점, 하위 선택창의 Escape 처리, 반응형 전환 후 복귀할
버튼은 공용 모달 훅의 옵션으로 표현했다. 저장소 key와 계정별 데이터 분리는
기존 기능이 소유하고, 접근 실패 처리만 공통 adapter가 담당한다.
초안 저장은 읽기 실패를 빈 목록으로 오인해 기존 데이터를 덮어쓰지 않도록 했다.

역할별 글자 크기는 활성 UI 글자 정책을 기준으로 계산한다. CSS 변수는 정의된
범위에서 계산되므로 루트·읽기 화면·고정 크기 화면 각각에서 같은 역할 정의를
평가한다. 초기 렌더링의 글자 크기와 문장 폭도 설정 기본값에서 생성한다.

재발 방지 규칙은 `AGENTS.md`, ESLint 플러그인 `tooling/eslint/sharedPaths.js`,
CSS 검사 `tooling/lintStyles.mjs`에 추가했다. `npm run lint`는 다음 우회를 검사한다.

- 공용 adapter 밖의 직접 localStorage/sessionStorage 접근
- 별도로 작성한 화면 폭 media query 문자열
- 컴포넌트의 고정 font-size utility/속성, 직접 RGB/hex 색 지정
- 공용 Button 밖에서 기본 버튼 스타일을 직접 조합하는 코드
- CSS 폭 미디어 쿼리의 숫자 직접 지정과 지원되지 않는 CSS var() 사용

검사는 구체적인 코드 형태에 적용된다. 서로 다른 이름으로 작성된 같은 업무 규칙이나
부적절한 variant 선택은 코드 리뷰에서도 확인해야 한다. 신규 추상화를 추가할 때는
기존 호출부 이관과 대체된 구현 제거까지 같은 변경에 포함한다.

검증 결과:

- 최신 main 반영 후 98개 테스트 파일, 701개 테스트 통과. 저장소 차단·용량 부족·초안 보존, 공통 입력
  높이와 글꼴 변경, 저장/임시 서식의 동등성, 린트 우회 방지와 CSS 정책 연동 포함.
- TypeScript strict 검사, ESLint/CSS 검사, 프로덕션 빌드 통과.
- 실제 Chromium에서 검색·키보드 이동·뒤로/앞으로 가기·새로고침·댓글·PDF 로딩
  실패와 재시도 검증 통과.
- 최신 main의 별도 기준 화면과 375/768/1440px 홈 및 데스크톱 설정 화면 비교:
  측정한 버튼 크기·글자 크기·문서 폭과 네 장의 스크린샷 픽셀이 동일했다.
- 실제 설정 슬라이더를 12pt에서 7pt로 변경했을 때 관련 역할 글자들이 함께 바뀌고
  가로 넘침 없이 반영되는 것을 확인했다. 외부 글꼴은 비교 환경을 맞추기 위해 차단했다.
- 책 입력창은 320~1800px의 9개 폭에서 기본·큰 글자 설정으로 단계 버튼 정렬과
  들여쓰기 애니메이션, 끝/중간 삽입, 연속 입력, 저장 실패 후 재시도를 검증했다.

브라우저 검증은 같은 출처의 가짜 Supabase 응답을 사용했다. 이 변경에는 운영 DB
마이그레이션이나 데이터 변경이 필요하지 않다.
