# 410pages 테마 영향 조사 — 2026-10-06

다른 테마에서도 재현된다. 원인은 **앱의 선택 테마와 Tailwind의 다크 모드 판단 기준이 서로 다름**이다. 밝은 고정 테마에서 시스템 다크 모드를 켜면 오류·성공 글씨가 옅어진다. 어두운 고정 테마에서 시스템 라이트 모드를 켜면 일부 설정 문구의 대비도 낮아진다.

앱 코드는 수정하지 않았다. 제안 설정은 독립 검사 CSS에만 적용했다.

## 범위와 근거

- 등록 테마 14개: 고정 밝은 테마 7개, 고정 어두운 테마 6개, Auto 1개. 실제 `lib/themeRegistry.ts`를 검사 페이지에서 가져왔다.
- `dark:` 사용처: 화면 파일 13개, 문자열 스타일 선언 32개. 호버만 바꾸는 선언과 글씨·바탕을 바꾸는 선언을 포함한 정적 목록이다.
- 현재 설정과 수정 후보 각각 14개 테마 × 시스템 모드 2개를 검사했다. 총 56개 조건, 대표 스타일 8종의 실제 계산 색상·바탕색 448개를 기록했다.
- [원본 검사 JSON](2026-10-06-theme-css-audit.json)에 색상, 반투명 바탕, 배경, 대비, 소스 위치를 보존했다. 사용자 계정·인증값·독서 내용은 포함하지 않았다.

## 원인

1. `features/settings/logic/preferencesDocument.ts`는 앱의 선택 테마에 맞춰 루트의 `.dark`와 `data-theme`를 바꾼다.
2. `tailwind.config.js`에는 `darkMode`가 없어 `dark:` 유틸리티가 시스템의 `prefers-color-scheme`를 따른다.
3. 앱 바탕색은 선택 테마를, 오류 글씨는 시스템 모드를 따르면서 서로 맞지 않는 색 조합이 생긴다.
4. 실제 사용자 탭에서도 앱 `day` / 앱 색상 체계 `light` / 시스템 다크가 동시에 확인됐다. 사용자 화면을 바꾸지 않고 검사 페이지에서 OS 모드를 재현했다.

[Tailwind v3 공식 문서](https://v3.tailwindcss.com/docs/dark-mode)는 기본 시스템 기준과 `.dark`를 따르는 `selector` 방식을 구분한다. 설치된 버전은 3.4.19다.

## 현재 CSS와 수정 후보 비교

각 수치는 28개 테마·시스템 조합에서 나온 최소 글씨/바탕 대비다. 글씨와 반투명 바탕은 해당 테마의 `--bg-card` 위에 합성했다.

| 대표 스타일 | 현재 최소 대비 | 앱 기준 후보 최소 대비 | 결과 |
|---|---:|---:|---|
| 로그인 오류 | 1.090:1 | 7.597:1 | 대비 회복 |
| 인증 성공 아이콘의 상태색 | 1.177:1 | 5.206:1 | 대비 회복 |
| 설정 오류 문구 | 1.865:1 | 4.745:1 | 대비 회복 |
| 설정 저장 성공 문구 | 1.498:1 | 5.388:1 | 대비 회복 |
| 서재·인용문 실패 복구 | 1.055:1 | 9.159:1 | 대비 회복 |
| 앱 전역 실패 알림 | 9.159:1 | 9.159:1 | 현재도 읽힘; 모드 선택을 통일 |
| 고정 빨간 삭제 글씨 | 3.313:1 | 3.313:1 | 별도 문제 유지 |
| 브랜드색 챕터 오류 | 3.037:1 | 3.037:1 | 별도 문제 유지 |

예: Mahler Light + 시스템 다크의 로그인 오류는 글씨 `rgb(254, 226, 226)` / 반투명 빨간 바탕 / 카드 `rgb(255, 253, 249)` 조합으로 1.092:1이었다. 앱 기준 후보에서는 고정 테마 13개 모두 시스템 라이트/다크를 바꿔도 대표 스타일 8종의 계산 색상·대비가 동일했다. Auto는 의도대로 시스템에 따라 바뀐다.

[W3C의 일반 크기 텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)은 4.5:1이다. 인증 성공 아이콘은 텍스트와 동일한 용도의 검증으로 취급하지 않으며, 표는 상태색의 수치만 보여준다. 화면 전체의 접근성 통과 판정은 아니다.

## 같은 원인으로 고쳐지지 않는 부분

- **고정 빨간 삭제 글씨:** 일부 메뉴는 `text-red-600`을 고정하고 `dark:`로는 호버 바탕만 바꾼다. 어두운 테마에서 카드 바탕 기준 최소 3.313:1이다. 다크 모드 기준을 바꿔도 글씨색은 그대로라 별도 색상 수정이 필요하다.
- **브랜드색 챕터 오류:** `index.css`의 `.chapter-hint[role="alert"]`는 `--accent`를 쓴다. Terminal Green에서는 오류도 녹색, Bach 계열에서는 갈색·금색이 된다. 카드 바탕으로 검사한 Airbnb Light와 Shostakovich Dark는 텍스트 대비가 4.5:1 미만이었다. 실제 챕터 화면 바탕에서는 재확인이 필요하다.
- **반증:** 앱 전역 실패 알림은 어두운 바탕색까지 함께 바뀌어 현재도 최소 9.159:1로 읽힌다. `dark:`가 있다는 이유만으로 모든 표시가 읽히지 않는다고 판단하면 안 된다.

## 수정 범위 제안

추천은 **① 공통 테마 판단 기준을 먼저 통일**하는 것이다. 이어 별도 고정색 문제를 확인된 범위에서 다루는 것이 가장 작고 재사용 가능하다.

| 선택지 | 얻는 것 | 남는 것 / 비용 |
|---|---|
| ① 공통 기준 통일 — 추천 | `tailwind.config.js`에 `darkMode: 'selector'` 한 항목을 추가. 기존 `.dark` 관리와 모든 `dark:` 사용처가 같은 기준을 따름. 새 테마도 등록부의 `scheme`에 따라 적용됨. | 고정 삭제색·브랜드색 오류의 의미 및 대비는 별도 점검. |
| ② 공통 기준 통일 + 오류·성공 의미색 정리 | 브랜드 강조색과 오류·성공색을 구분해 테마가 늘어도 상태의 의미를 유지. | 영향을 받는 여러 컴포넌트의 표현 선택과 전환이 추가로 필요. |
| ③ 로그인 문구만 수정 | 한 화면의 즉시 가독성 개선. | 다른 화면과 다음 컴포넌트에서 같은 원인이 남음. 추천하지 않음. |

`--accent`로 오류 글씨를 일괄 치환하거나 테마별 하드코딩을 늘리는 방법은 추천하지 않는다. 기존 테마 등록부·공통 판단 기준을 재사용하는 것이 확장에 유리하다.

## 검증 수준과 미검증

- 확인: 저장소의 전체 테마 등록부, `dark:` 정적 사용처, 독립 페이지의 실제 CSS 렌더링과 계산 색상, 현재/후보 56조건의 색상 비교.
- 검사 CSS에서 외부 서체 `@import`만 제외했다. 색상·테마 규칙은 원본 컴파일 결과를 그대로 썼다. 서체·글자 크기·레이아웃 변경의 검증은 이번 목적에 포함하지 않는다.
- 미검증: 각 오류를 실제 앱 사용 흐름에서 모두 발생시킨 것, 호버·포커스 모든 상태, 실제 기기·다른 브라우저, 실제 로그인 성공/실패, 배포 후 결과.
- 앱 코드·사용자 설정·데이터 변경 없음. 제안은 확정 Policy가 아니다. 비교 HTML은 초안이며 아직 선택·적용하지 않았다.
