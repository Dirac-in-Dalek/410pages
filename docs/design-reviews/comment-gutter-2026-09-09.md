# 댓글 여백 배치 구현 — 2026-09-09

## 사용자 결정
- 댓글을 왼쪽 패널 끝과 인용문 본문 시작 사이의 여백 가운데에 둔다.
- 왼쪽 패널을 접어도 인용문 위치는 유지하고 댓글만 이동한다.
- 댓글 상단을 원문과 맞추고, 댓글 사이의 선은 없앤다. 인용문 구분선은 원문 영역에만 둔다.
- 관련 확정 Policy: ../policies/memo-workspace.md

## Codex 결정
- 기존 Tailwind와 CSS grid/container 단위를 사용했다. 새 의존성이나 저장 상태는 추가하지 않았다.
- 왼쪽 패널의 저장된 너비를 기준으로 책 본문 너비와 위치를 계산한다. 패널 접힘에 따라 본문을 다시 가운데로 옮기지 않는다.
- 책 제목과 하단 입력창도 같은 본문 기준선을 사용한다.
- 댓글 너비는 기존 16rem을 유지한다. 기존 체크박스와 본문 내부 여백 3rem을 포함하여 실제 글자 시작점까지의 여백을 계산한다.
- 기존 자동 접힘 판단은 전체 가용 너비 대신 실제 댓글 여백으로 측정한다. 댓글 16rem에 양쪽 여유 3rem을 더한 19rem을 기준으로 사용했다. 패널 접힘 애니메이션 중에는 최종 여백을 계산한다.
- 댓글 사이 추가 여백은 0.75rem이다. 기존 글자 시작 여백과 입력칸 하단 정렬을 유지했다.
- 책 본문 요소가 아직 없으면 공간 측정을 생략한다.

## 기존 동작 유지
- 공간 부족 시 홈 패널, 다음으로 책 메모 패널을 접는 기존 순서.
- 홈을 수동으로 다시 펼칠 때 댓글을 닫는 기존 정책.
- 모바일 댓글 시트와 모바일 댓글 사이의 선.
- 댓글 추가·수정·삭제·실패 복구, 전체 펼침과 단일 입력창, 긴 쪽에 맞추는 행 높이.
- 책 전체 메모 및 데이터/API. 운영 배포와 Figma 수정은 하지 않았다.

- 1440px: 댓글과 책 메모 동시 표시 확인, 가로 넘침 없음.
- 375px: 책 화면 시각 확인, 데스크톱 댓글 열 없음, 가로 넘침 없음.
- 관련 테스트 3개 파일, 23개 테스트 통과. 실제 여백 기반 접힘과 댓글 선 제거 회귀 테스트 추가.
- TypeScript 검사 및 Vite build 통과. 기존 번들 크기와 Browserslist 갱신 경고 존재.

## 미검증 사항
- 실제 사용자 데이터 저장은 실행하지 않았다. 저장·편집·실패 동작은 자동 테스트로 확인했다.
- 모든 글자 크기·패널 최대 너비 조합과 다른 브라우저는 미검증. 좁은 화면에서 양쪽 패널을 매우 크게 여는 기존 한계에 새 정책을 추가하지 않았다.

- 기존 유지: 홈을 다시 펼치면 댓글을 닫는다. 댓글 없는 인용문에 빈 입력창을 생성하지 않는다. 모바일과 다른 화면에는 적용하지 않는다.

- 기존 유지: 패널 너비 조절, 접힘 애니메이션, 댓글 전체 펼침, 모바일, 메모 저장 로직.
- 검증: 로컬 1440px에서 우측 접힘 전후 본문 열 x=459px 확인. 관련 14개 테스트와 TypeScript 검사 통과. 기준 너비 불변 회귀 검증 추가 후 패널 테스트 8개 재통과. check 빠른 검토 완료.
