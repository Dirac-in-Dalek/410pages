“더 넓은 화면에서는 어떻게 해야 할지”

이것이 다음 턴의 정확한 질문입니다. 특정 4K 화면을 채우는 일이 아니라, 실제 가용 CSS viewport가 넓어질수록 글자·본문 폭·양쪽 열·간격·바깥 여백·조작 밀도를 어떤 원리로 함께 바꿀지 정합니다.

이번 턴은 1024px 중앙 정렬, 보이는 세 열 1:2:1, 스크롤 중 막대 표시, 메모 헤더 조작과 저장 UI 정리까지 완료합니다. 현재 큰 화면에는 읽기 묶음 폭 상한이 있습니다. 이 구현 한계와 다음 연구 질문의 범위를 구분합니다.

4K 가용 폭을 그대로 898/1796/898px로 늘리면서 본문 글자 18.67px을 유지하는 안은 읽기 행이 지나치게 길어집니다. 폭 하나만 키우는 방식은 다음 비교 후보에서 제외합니다.

문제 정의

가용 폭은 모니터 해상도 하나로 정해지지 않습니다. 같은 창에서도 서재·메모가 열렸는지, 사용자가 고른 글자 크기, 브라우저 zoom, OS 표시 배율과 물리 DPR에 따라 실제로 읽는 크기와 남는 공간이 달라집니다. 그래서 픽셀 폭 하나를 4K 정답으로 정하지 않고 여러 폭의 연속 범위에서 관계를 검증합니다.

다음 턴에서 함께 볼 변수

  • 글자: 본문·메모 글자 크기, 행간, 한 줄 글자 수와 장시간 읽기 밀도.
  • 본문 폭: 인용문의 읽기 행 길이와 제목·하단 입력창의 동일한 시작선·폭.
  • 양쪽 열: 댓글의 짧은 문장과 메모의 긴 글이 필요한 서로 다른 최소·최대 폭.
  • 여백: 세 열 사이 거리, 읽기 묶음 바깥 여백, 서재가 열린 경우의 남는 공간.
  • 컨트롤 밀도: 메모 헤더·접기 버튼·입력 조작이 커진 글과 어울리는 크기와 간격.

1440 / 1920일반 데스크톱에서 글자와 행 길이가 언제 바뀌어야 하는지 비교.

각 화면은 CSS viewport 크기, 서재·메모의 열린 상태, 사용자 글자 설정, 브라우저 zoom, 디스플레이의 물리 DPR을 따로 기록합니다. 현재 IAB의 4K 축소 표시는 실제 4K 모니터에서 보는 물리적 글자 크기와 같다고 간주하지 않습니다. 표의 다섯 폭 사이도 확인해 breakpoint 주변과 연속 변화에서 튀는 구간을 찾습니다.

다음 턴에 비교할 세 원리

방향얻는 것과 잃는 것
연속 확대가용 폭에 따라 글자·열·간격을 부드럽게 키워 화면 크기 사이의 변화가 자연스럽습니다. 반면 읽기 행이 너무 길어지거나 작은 폭 변화에도 글자가 계속 움직일 수 있습니다.
구간별 단계 확대몇 개의 폭 구간마다 검증된 글자·열·간격 묶음으로 바꿔 결과를 통제하기 쉽습니다. 경계에서 갑자기 배치가 바뀌고 다양한 zoom·패널 조합을 놓칠 수 있습니다.
읽기 단위 기준 확대본문의 적정 행 길이(ch 또는 실제 한 줄 글자 수)를 우선하고, 남는 공간을 양쪽 열·간격·바깥 여백에 배분합니다. 읽기 목적과 직접 연결되지만 글꼴·언어·사용자 글자 설정에 따라 측정과 규칙이 더 필요합니다.

추천 가설: 읽기 단위를 중심에 두고, 조작 밀도와 큰 구조 변화만 구간별로 조정하는 혼합 방향을 먼저 비교합니다. 본문 행 길이를 통제하면서도 zoom·DPR·패널 상태에 대응할 가능성이 가장 큽니다. 아직 채택한 설계나 픽셀 값은 아닙니다.

가설이 틀렸음을 보여 줄 증거: 적정 행 길이를 유지해도 넓은 화면에서 시선 이동이 불편하거나 공간이 낭비된다는 사용자 관찰, 언어·글꼴별 줄바꿈 차이로 규칙이 자주 깨지는 화면, breakpoint 방식이 더 일관되고 읽기 편한 비교 결과가 나오면 추천을 바꿉니다.

다음 실행 순서

  1. 동일한 긴 인용문·짧은 댓글·긴 메모 fixture로 1024/1440/1920/2560/3840과 그 사이 연속 폭을 수집합니다.
  2. 글자·본문 폭·양쪽 열·여백이 함께 달라지는 구조적으로 다른 세 방향을 만듭니다.
  3. 한 줄 길이, 읽기 이동 거리, 메모 작성 공간, 남는 여백, 컨트롤 밀도를 같은 표로 비교합니다.
  4. 추천 방향과 포기하는 점, 틀렸음을 보여 줄 관찰을 제시하고 사용자가 한 방향을 선택합니다.
  5. 선택 뒤에만 시안을 구현하고 실제 viewport·표시 배율·물리 화면을 구분해 검증합니다.

이 문서는 다음 턴의 설계·검증 계획입니다. 아직 넓은 화면의 글자 크기, 열의 픽셀 폭, breakpoint 또는 확대 공식을 확정하지 않았고 제품 코드에도 적용하지 않습니다. 4K는 목표 전체가 아니라 여러 검증 조건 중 하나입니다.
