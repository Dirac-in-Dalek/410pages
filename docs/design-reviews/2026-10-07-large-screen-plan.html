“더 넓은 화면에서는 어떻게 해야 할지”

이것이 다음 턴의 정확한 질문입니다. 특정 4K 화면을 채우는 일이 아니라, 실제 가용 CSS viewport가 넓어질수록 글자·본문 폭·양쪽 열·간격·바깥 여백·조작 밀도를 어떤 원리로 함께 바꿀지 정합니다.

사용자 목표: 1024와 넓은 화면을 같은 모습으로 만들지 않습니다. 화면이 넓어지면 글자도 커지지만, 열 폭·열 사이 간격·문장 사이 여백이 더 여유롭게 변해야 합니다. 1:2:1을 지켰다는 숫자만으로 “시원하게 보인다”고 판정하지 않습니다.

읽기 설정 교정: 사용자는 글자 크기를 조절합니다. 인용구 너비는 화면 비율로 자동 계산합니다. 기존 37rem 같은 너비 조절 칸은 제거할 대상이며, 글자 크기 선택과 본문 폭 계산을 하나로 묶지 않습니다.

이 문서는 구현 전 검토를 보존한 계획 기록입니다. 승인한 방향을 제품 코드에 적용했으며 실제 구현값·캡처·검증 범위는 넓은 화면 구현 결과에서 확인할 수 있습니다.

사용자가 고른 글자 크기가 기준입니다. 별도 확대 모드를 추가하지 않고, 그 기준에서 가용 폭에 따라 완만하게 커지는 반응형 값을 추천합니다. 설정값은 보존하고 zoom 확대를 상쇄하지 않습니다. 현재 기본 14pt(약 18.67px)에서 넓은 화면의 20~24px은 비교할 미확정 후보이며 높이에 대응시킨 값이 아닙니다. CSS clamp()는 유동적인 최소·선호·최대값을 표현할 수 있지만, 어떤 값이 편안한지를 결정해 주지는 않습니다.

같은 CSS viewport만 보고 물리 모니터 크기나 시청 거리를 추정하지 않습니다. zoom·DPR·물리 해상도는 별도로 기록하며 viewport 기반 글자 계산으로 사용자의 확대를 되돌리지 않습니다. WCAG Reflow 설명도 물리 해상도와 CSS viewport를 구분합니다.

서재와 메모 열 처리

왼쪽 서재는 댓글·본문·메모의 기본 1:2:1 읽기 비율 밖에 있습니다. 2026-10-07 사용자 교정: 서재도 화면 확대에 맞춰 글자·아이콘·행 높이·폭이 함께 커져야 합니다. 기존의 “서재 폭은 화면 확대에 따라 키우지 않는다”는 제안은 철회합니다. 메모는 오른쪽 읽기 열입니다. 메모를 접어도 같은 열 헤더와 펼치기 버튼, 초안·커서·스크롤을 유지합니다.

관계적용할 동작
서재와 댓글 사이 여유가 있음서재가 커지는 동안 여유 공간을 사용합니다. 서재 크기가 바뀌었다는 이유로 댓글의 폭이나 위치를 추가로 바꾸지 않습니다. 화면 자체 확대에 따른 기본 읽기 배치는 별도로 적용합니다.
서재가 댓글에 닿을 정도로 커짐서재·댓글 사이 필요한 간격이 소진된 지점부터 댓글 폭만 줄입니다. 본문 중심·본문 폭·메모 폭·위치는 서재 때문에 바뀌지 않습니다.
댓글을 좁히는 방향 · Codex 추천댓글의 본문 쪽 오른쪽 경계를 고정하고, 왼쪽 경계를 안으로 밀어 좁힙니다. 인용문과 댓글 사이 연결과 간격을 보존하며 긴 댓글은 줄바꿈합니다.
서재가 다시 작아짐충돌 때문에 줄었던 댓글 폭만 원래 기본 폭까지 복원합니다. 그 이후 서재가 더 작아져도 댓글은 더 넓어지거나 움직이지 않습니다.

계산 순서: 화면 중심과 공통 확대 기준으로 기본 본문·댓글·메모 위치를 먼저 구합니다. 다음으로 서재의 실제 오른쪽 끝을 측정하고, 댓글과의 충돌량만 댓글 폭에서 뺍니다. 현재의 bookReadingColumns.ts는 왼쪽 가용 폭이 줄면 세 열을 함께 좁히므로 이 계산을 분리해야 합니다. 서재 폭을 좌우 양쪽에서 똑같이 빼는 이전 제안은 새 관계에 적용하지 않습니다.

댓글 폭 = min(기본 댓글 폭, 댓글 오른쪽 끝 − 서재 오른쪽 끝 − 필요한 간격)
댓글 왼쪽 끝 = 댓글 오른쪽 끝 − 댓글 폭

위 식은 댓글을 읽고 입력할 수 있는 최소 폭까지의 충돌 구간에 적용합니다. 최소 폭과 그 이후의 동작은 아직 미정입니다. 즉시 서재를 접는 대신 먼저 댓글을 좁히며, 더 좁힐 수 없을 때 기존 자동 접기·임시 겹쳐 열기를 후속 후보로 검토합니다. 충돌 기준 간격도 화면 확대에 맞춰 조절하되 실제 값은 작업대에서 확인합니다.

1:2:1 적용 범위: 충돌이 없는 기본 읽기 배치는 1:2:1입니다. 서재와 충돌할 때에는 사용자가 정한 댓글 축소가 우선하므로 댓글만 더 좁아집니다. 이때 본문·메모까지 줄여 비율을 강제로 유지하지 않습니다. 기존 독립 메모 폭 조절과 사용자의 수동 접기·펼치기도 보존합니다.

확장성 기준: 화면 크기와 사용자 원본 설정에서 매번 계산합니다. 이전 표시 결과를 다음 입력으로 사용해 배율이 누적되지 않게 합니다. 새 컴포넌트는 이 결과의 역할별 값만 소비하며 새로운 화면별 숫자나 별도 배율 함수를 복사하지 않습니다. 전체 화면의 transform 확대나 브라우저 zoom 조작을 사용하지 않습니다.
