# YES24 연결 및 챕터 인수인계 구현 점검

## 최신 용어 복원 및 브라우저 피드백

- 사용자 결정: 우선 `구분선` 용어를 `챕터`로 되돌린다.
- Codex 결정: 추가·제목·저장·취소·접기·펼치기·삭제 및 오류 안내와 접근성 이름을 함께 변경했다. 내부 식별자는 유지했다.
- 기존 동작 유지: 접기 범위·초안 보존·저장 구조·정렬은 변경하지 않았다.
- 검증: 관련 테스트 6개 파일 42개 통과, 공백 검사 통과. 문구 변경에 새 테스트는 추가하지 않았다.
- 미검증 사항: 이번 문구 변경 후 실제 브라우저 화면 확인. 운영 배포는 하지 않았다.
- 남은 사용자 결정: 용어 복원에는 없음. 아래 후속 구현 중 새로운 동작·구조 결정이 필요하면 별도 확인한다.
- 후속 요청: 410pages 로고를 상단 검색 영역으로 이동; 홈 접기 버튼은 오른쪽 패널처럼 위치를 유지하고 애니메이션 적용; 맨 위 추가 위치도 선·호버 방식으로 통일; 챕터 더블 클릭 제목 수정과 드래그 위치 이동; 메모 패널 제목을 `메모`로 변경. 이번에는 사용자의 `일단` 지시에 따라 용어 복원부터 적용했다.

## 구현 범위

- 제목·저자로 YES24 책을 찾고, 일치하는 후보가 하나일 때 표지를 연결한다. 결과는 브라우저에 기억한다.
- 권수를 쓰지 않은 시리즈는 원작 1권 표지를 연결한다. 1권 목차·ISBN을 시리즈 전체 정보로 사용하지 않는다.
- 목차 원문 조회와 캐시는 구현했다. 원문을 챕터로 변환하거나 인용문을 자동 배치하는 기능은 아직 구현하지 않았다.
- 인수인계에서 목록 맨 위·빈 책의 챕터 추가, 본문형 챕터 제목, 책 행의 Enter/Space 탐색 제거를 반영했다.

## 사용자 결정

- YES24 사용, 공백·저자 역할 표기 정리, 애매한 후보는 자동 선택하지 않음, 브라우저 캐시.
- 시리즈는 1권 표지 사용. 판본은 별도 책으로 관리.
- 입력 페이지가 클릭한 챕터보다 우선. 기존 자료는 자동 재분류하고 되돌리기 제공.
- 하단 고정 입력창과 책 본문형 챕터. 세부 확정 사항은 기능별 Policy 참조.
- 추가 승인: 페이지 판별 실패 시 선택 챕터 또는 미분류에 저장, 챕터는 목차 순·인용문은 페이지 순, 초기 펼침·접속 중 접힘 유지·저장 후 선택 유지. 정책 확정이며 관련 앱 동작은 구현 전이다.

## Codex 결정

- 키는 서버 환경변수로만 사용하고 기존 Supabase 로그인으로 조회 요청을 인증한다.
- HTTPS YES24 이미지 주소만 허용하고, 후보 목록이 일부만 반환되면 자동 확정하지 않는다.
- 중복 요청을 합치고 순서대로 조회한다. 실패·후보 없음은 캐시에 남기지 않는다.
- 이미지 로딩 중에는 기존 책 모양을 보여 주고, 이미지 실패 시 해당 캐시를 지운다.
- 표지가 없어도 정확히 일치하는 책의 목차 원문은 유지한다.
- 시리즈 1권 표지는 시리즈 전체의 ISBN·목차로 확장하지 않는다.
- 위 구현 판단은 사용자 승인 정책으로 추가하지 않았다.

## 기존 동작 유지

- 표지를 찾지 못하면 기존 CSS 책 모양을 유지한다. 저자 사진 연결은 기존과 같이 미구현이다.
- 기존 수동 구분선 데이터와 저장 구조를 유지했다. 계층·재분류·판본 분리 DB 변경은 적용하지 않았다.

## 검증 및 한계

- 실제 YES24 조회에서 롱 뷰의 표지와 목차 원문을 확인했다. 목차에는 시작 페이지가 없었다.
- 광마회귀는 원작 1권 후보와 표지를 확인했다. 1권의 목차는 회차 범위만 제공했다.
- 빌드·타입 검사 통과. 배포 산출물에 설정한 API 키가 포함되지 않음을 검사했다.
- 로컬 앱은 로그인 화면까지 확인했다. 로그인 후 실제 사용자 책 목록에서 표지가 표시되는 전체 흐름은 미검증이다.
- 운영 배포, DB 변경, 커밋은 수행하지 않았다.

## 남은 사용자 결정

- 챕터 계층·시작 페이지·인용문 소속의 저장 구조, 페이지 누락·동일 페이지의 세부 정렬 순서.
- 목차 원문 변환·시작 페이지 편집·범위 중첩·재조회·기존 목차 병합 규칙은 챕터 Policy의 미결정 항목을 따른다.

## 구분선 정정 후 변경 감사

- 사용자 결정: 기능 이름은 `구분선`이다. 별도 챕터 관리 대상으로 확장한다는 해석을 철회했다.
- Codex 결정: 화면의 추가·제목·저장·취소·삭제·오류 안내 및 접근성 이름을 함께 통일했다. 내부 타입·파일 이름은 바꾸지 않았다.
- 기존 동작 유지: 구분선 저장 형식, 목록 위치, 추가·삭제·오류 복구 동작은 그대로다. 앞서 승인한 접기·입력 위치 요구는 취소하지 않았다.
- 검증: 관련 기존 테스트 5개 파일 38개 통과. diff 공백 검사 통과. 이번 변경은 표시 문자열뿐이며 새 테스트는 추가하지 않았다.
- 미검증 사항: 실제 로그인 환경에서 수정된 문구 확인. 접기·페이지 배치·목차 자동 변환은 아직 미구현이다.
- 남은 사용자 결정: 구분선을 접을 때 다음 구분선까지만 숨길지, 하위 구분선까지 함께 숨길지, 접기를 제외할지. 저장 구조 확장 질문은 철회 상태다.

## 구분선 접기 구현 감사

- 사용자 결정: 다음 구분선 직전까지 숨긴다. 처음에는 모두 펼치고 접힘 상태는 접속 중 유지한다.
- Codex 결정: 구분선 왼쪽에 44px 버튼을 두고 키보드 조작과 펼침 상태 안내를 제공했다. 접힌 본문은 삭제하거나 컴포넌트를 제거하지 않고 화면에서 숨겨 입력 상태를 보존했다. 마지막 구간에서는 목록 끝까지 숨긴다. 숨긴 내용 사이에 추가 버튼이 노출되지 않도록 했다.
- Codex 오류 처리 보완: 구분선 접기 버튼은 인용문 옆 댓글 패널의 외부 클릭 닫기 대상에서 제외했다. 구분선 조작으로 작성 중인 댓글이 소실되는 문제를 구조 검토에서 발견하고 수정했다.
- Codex 구현 세부: 로그인된 AppShell에 구분선 ID 집합을 두고 ArchiveScreen을 거쳐 CitationList에 전달한다. 서버나 브라우저 영구 저장소는 추가하지 않았다. 계정별로 AppShell이 다시 생성되는 기존 구조를 사용한다.
- 기존 동작 유지: 구분선·인용문의 저장 형식, 목록 순서, 삭제·실패 복구, 하단 입력창 위치를 유지했다.
- 검증: 관련 4개 테스트 파일 28개 통과. 다음 구분선 경계, 마지막 내용 구간, 빈 구간, 펼치기, 키보드 Enter, 목록 재생성 후 접힘 복원, 숨긴 본문 유지 검증. 댓글 작성 후 실제 포인터 클릭으로 접고 펼쳐 초안이 유지되는 회귀 테스트는 수정 전 실패, 수정 후 통과했다. 빌드·타입·공백 검사 통과.
- 미검증 사항: 실제 로그인된 브라우저와 휴대폰에서의 조작. 현재 테스트는 컴포넌트 검증이며 실제 앱의 로그아웃·재로그인 검증은 아니다. 운영 배포는 하지 않았다.
- 남은 사용자 결정: 접기 범위 선택은 완료했다. 목차 변환·페이지 범위와 그 밖의 미결정 사항은 기능 Policy에 남아 있다. 이번 작업에서 새로 확정하지 않았다.
