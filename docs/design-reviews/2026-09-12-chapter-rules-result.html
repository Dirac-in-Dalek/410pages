자동 테스트 473개·타입 검사·빌드와 개발/빌드 브라우저 검증이 통과했다.

운영 DB 변경과 배포는 이번 작업에서 실행하지 않았다.

후속 상태 · 운영 DB 적용 완료: 2026-09-12 사용자 승인으로 단계 필드를 추가했다. 기존 챕터 34개의 내용·순서 보존, 기본 단계 0·음수 금지·RLS 유지를 확인했다. 아래 구현 기록과 달리 DB 단계는 완료됐으며 앱 배포는 사용자 확인 후 별도 결정한다.

반영한 동작

  1. 구분선에서 추가하면 앞 챕터와 같은 단계. 2.1 바로 밑의 추가는 2.2 위치다. Tab을 누르지 않아도 된다. 인용문 사이에서도 그 위치의 앞 챕터 단계를 사용한다.
  2. 번호를 자동으로 붙이지 않음. “작은 관찰”, “함께 읽기”처럼 사용자가 쓴 제목을 그대로 표시한다. 2.2는 위치를 설명하는 예시다.
  3. 상위 챕터를 접으면 하위 전체를 숨김. 모든 하위 챕터와 인용문을 숨기고 다음 같은 단계·상위 단계 챕터는 남긴다.

Tab·Space를 별도로 누르면 하위로, Delete·Backspace를 누르면 한 단계 밖으로 이동한다. 제목 맨 앞의 커서에서만 적용하는 기존 조건은 유지한다.

추가로 수정한 문제

  • 키보드 편집·추가 미리보기에 임시 단계를 포함한 전체 챕터 계산을 사용한다. 저장 전·후 관계가 같고 취소하면 원래 들여쓰기와 연결선으로 돌아간다.
  • 접힌 챕터 뒤의 추가·드래그는 숨겨진 내용 전체 뒤에 놓는다. 검색으로 목록에서 빠진 인용문도 포함하며, 목록 맨 끝 구분선에도 같은 기준을 사용한다.

  • 기존 드래그 미리보기·저장 실패/재시도·취소·최상위 복귀 검사도 통과.
