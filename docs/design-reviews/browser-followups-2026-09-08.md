# 브라우저 후속 수정 점검

## 댓글 글자 시작선 정렬

- 사용자 결정: 저장된 댓글의 시작선을 댓글 입력칸의 글자 시작선에 맞춘다.
- Codex 결정: 인라인 댓글 목록에 입력칸과 같은 좌우 6px 여백을 적용했다.
- 기존 동작 유지: 댓글 칸 너비·행 하단 입력·저장·모바일 표시.
- 미검증: 변경 후 실제 브라우저의 픽셀 좌표 비교.
- 남은 사용자 결정: 없음.

## 전체 댓글 조작 위치와 메모 동시 표시

- 사용자 결정: 전체 댓글 조작을 인용문 아래 메모 개수 옆으로 이동한다. 인용문 댓글과 책 전체 메모를 함께 사용하려는 요구를 반영한다.
- Codex 결정: 각 인용문의 `메모 N` 옆에 `전체 펼치기/접기` 버튼을 배치하고 책 제목의 버튼·전용 속성을 제거했다. 클릭 전파를 막아 전체 조작이 해당 인용문 열기까지 중복 실행되지 않게 했다.
- 오류 수정: 책 전체 메모를 여는 함수에서 개별·전체 댓글 상태를 강제로 초기화하던 코드를 제거했다. 메모 열기 버튼과 메모 패널 내부 조작을 댓글 외부 클릭 닫기 대상에서 제외했다.
- 기존 동작 유지: 공간 부족 시 홈·전체 메모를 순서대로 접는 기존 규칙, 모바일의 한 번에 한 시트 표시, 저장 경로·초안 복구.
- 미검증: 실제 브라우저에서 메모를 다시 열고 저장까지 진행하는 전체 과정, 운영 배포. 메모 패널 자체를 새 디자인으로 재설계한 것은 아니다.
- 남은 사용자 결정: 전체 메모의 새로운 표현 방식은 확정하지 않았다. 이번 수정은 동시 사용을 막던 동작과 전체 댓글 버튼 위치를 고친 것이다.

## 패널 너비와 댓글 간격

- 사용자 결정: 양쪽 패널 너비 232~960px, 같은 브라우저에서 기억. 댓글과 본문은 약간 더 띄운다. Tab을 이용한 챕터 단계 변경은 구현하지 않고 검토만 한다.
- Codex 결정: 댓글 전체 펼치기를 책 제목 바로 오른쪽으로 이동했다. 경계선 조작 영역은 8px, 방향키 조절은 16px 단위로 제공한다. 너비는 드래그 시작값과 마우스 이동량으로 계산하며 조절 중에는 너비 애니메이션을 끈다. 브라우저 저장이 막혀도 현재 화면의 크기 조절은 동작한다.
- Codex 시각 조정: 패널 크기가 바뀌어도 검색줄이 흔들리지 않게 로고·계정 영역 너비를 고정했다. 댓글 간격은 12px에서 20px로 늘리고 본문 위치 예약 공간과 자동 접기 폭 계산도 함께 맞췄다.
- 기존 동작 유지: 모바일 화면, 댓글 입력 하단 배치, 메모 자동 저장, 패널 접기 애니메이션과 댓글 공간 확보 순서.
- 검증: 실제 2560px 화면에서 양쪽 경계선을 마우스로 드래그해 각각 500px로 바뀌는 것을 확인한 뒤 검증 전 너비로 복원했다. 범위 제한·브라우저 기억은 테스트로 확인했다.
- 미검증: 실제 브라우저 재시작 후 복원, 운영 배포. 작은 데스크톱에서 양쪽 너비 합이 화면보다 커지는 조합은 별도 검증하지 않았다.
- 남은 사용자 결정: 패널 범위·기억 방식은 확정 완료. 챕터 계층 조작은 검토 상태다.

## 댓글 칸 하단 입력 및 표시 정리

- 사용자 결정: 댓글 입력창을 해당 댓글 칸 하단에 배치; 댓글 날짜·댓글 쪽수 제목·책 화면 인용문 날짜 제거; 페이지 입력칸 확장과 전송 버튼 옆 오른쪽 정렬; 메모 패널 시각적 통일.
- Codex 결정: 댓글 칸을 행 높이만큼 늘리고 입력창에 margin-top:auto 적용. 기존 20px 아래 여백 유지. 메모는 댓글과 같은 sans 글꼴·14px 크기·24px 줄높이, 본문 여백 12px로 맞추고 하단 경계선을 제거했다. 페이지 칸 외부 너비는 7.5rem이며 아이콘 크기를 유지한다.
- 기존 동작 유지: 원문 페이지·메모 개수, 댓글 닫기·수정·삭제, 저장·초안 복구. 기존 모바일 댓글 패널의 날짜·제목은 유지하며 날짜·제목 삭제는 인용문 옆 댓글에 적용했다. 저장된 날짜 값은 변경하지 않았다.
- 실제 화면 검증: 데스크톱에서 댓글 입력창과 댓글 칸 아래 좌표가 동일함을 확인했다. 페이지 입력 텍스트 너비 78px 및 전체 플레이스홀더 표시 확인. 375px 모바일에서도 페이지 입력칸과 전송 버튼이 우측에 나란히 들어가며 가로 넘침이 없었다. 화면 크기를 복원했다.
- 미검증: 실제 휴대폰 키보드와 운영 배포. 저장 로직은 이번에 변경하지 않았다.
- 남은 사용자 결정: 이번 UI 수정에는 없음.

## 사용자 결정

- 410pages 로고를 상단 검색줄로 이동.
- 홈 패널 버튼은 접기·펼치기 후에도 같은 위치, 패널 전환 애니메이션.
- 맨 위 챕터 추가도 선과 호버 표시 사용.
- 챕터 더블 클릭 제목 수정, 드래그 이동 기능 요청.
- 메모 패널 화면 제목을 `메모`로 변경.

## Codex 결정

- 홈 버튼은 왼쪽 16px에 고정, 패널은 기존 오른쪽 패널과 같은 200ms 너비·투명도 전환을 사용한다. 모션 축소 설정을 따른다. 접힌 패널은 inert로 키보드·보조기술 접근을 차단한다.
- 자동 접기 판단은 애니메이션 종료 후 확보되는 폭으로 계산한다. 전환 도중 메모까지 불필요하게 접히는 문제를 검토에서 찾아 회귀 테스트로 보완했다.
- 로고는 기존 색·글꼴을 그대로 사용한다. 검색줄 좌우 여백은 접힘 여부에 따라 바뀌지 않는다.
- 선 위 표시에는 키보드 포커스와 터치 화면 대안을 유지했다.
- 더블 클릭 외에 수정 버튼을 제공한다. Enter 저장, Escape·취소로 편집 종료, 한글 조합 중 Enter 무시. 실패 시 입력한 제목을 유지한다.
- 제목 수정은 기존 chapter_blocks의 label만 갱신하며 사용자·책·행 ID 조건으로 제한한다. 새 DB 구조·권한 변경은 없다.

## 기존 동작 유지

- 인용문과 댓글 저장·접기, 챕터 목록 위치, 메모 자동 저장은 유지한다.
- 메모 입력란의 접근성 이름은 다른 댓글 입력과 구별하도록 `책 전체 메모`를 유지한다.

## 검증

- 관련 6개 테스트 파일 59개 통과, 빌드·타입·공백 검사 통과.
- 실제 로컬 화면에서 상단 로고·메모 제목·챕터 추가 선을 확인했다. 홈 버튼은 접기 전후 모두 x16, y58.898px로 유지됐다.

## 미검증 사항

- 서버에 실제 챕터 제목을 변경하고 재접속하는 전체 과정. 단위 테스트로 요청 범위와 실패 처리를 검사했다.
- 제목 수정의 별도 보안 검토자는 검토를 완료하지 못했다. 본 작업에서는 사용자·책·행 조건 제한과 실패 처리 코드를 직접 확인하고 API 테스트로 검증했다. 별도 보안 검토 통과로 보고하지 않는다.
- 운영 배포는 하지 않았다.

## 남은 사용자 결정

- 사용자가 `제목만` 이동을 선택했다. 이 항목의 추가 선택은 없다.

## 챕터 제목만 이동 — 추가 구현 감사

- 사용자 결정: 챕터 제목만 이동하며 인용문과 댓글 위치는 유지한다.
- Codex 결정: HTML 기본 드래그를 제목·이동 손잡이에 적용하고 대상 행의 위·아래를 드롭 위치로 사용한다. Alt+위/아래는 인접 행을 넘어 이동하는 키보드 대안이다. 위치 표시선은 드래그 중에만 보인다.
- Codex 위치 계산: 기존 정렬값의 중간값 계산을 재사용한다. 검색으로 숨겨진 항목도 포함한 같은 책 전체 데이터에서 경계를 계산한다. 단어 묶음은 변할 수 있는 묶음 ID 대신 실제 첫·마지막 단어를 기준으로 계산한다.
- Codex 오류 처리: 저장 응답이 성공한 뒤 화면 위치를 갱신하며 실패하면 기존 위치를 유지한다. 숫자 정렬값 사이에 정확히 들어갈 여지가 없으면 오류를 보여주고 이동하지 않는다. 인용문 위치를 강제로 바꾸지 않는다.
- 기존 동작 유지: 제목·댓글·인용문 내용과 인용문의 정렬값을 유지한다. DB 변경은 해당 사용자·책·챕터 행의 created_at_sort 한 필드뿐이다. page_sort는 기존 값 그대로이며 현재 책 화면은 기존 작성 순서 기반 표시를 유지한다.
- 실제 검증: 서버 저장 없는 임시 화면에서 키보드로 제목만 이동하고 인용문 10→30→50 순서가 유지됨을 확인했다. 임시 파일·탭은 제거했다.
- 미검증: 자동 브라우저 도구의 마우스 드래그는 dragstart·dragend만 전달되어 실제 drop 성공을 확인하지 못했다. 드롭 경로는 컴포넌트 이벤트 테스트로 검사했다. 실제 서버 저장 후 재접속 검증·운영 배포는 하지 않았다.
- 남은 사용자 결정: 제목만 이동 범위는 확정 완료. 이전 목차 자동 적용 등 별도 미완료 기능은 해당 Policy에 남아 있다.
