# 410pages 사용자 시나리오와 UX 개선안 — 재검토

작성·재검토: 2026-09-08 · 현재 단계: 분석·제안. UI 재설계·구현은 다음 단계.

후속 검토: [현재 운영 화면의 UI 중요도 리뷰](./visual-hierarchy-2026-09-08.md).

## 사용자 결정

- 저장 상태는 보여줄 필요가 없다. 저장 중·저장됨 확인을 사용자 시나리오의 목표로 삼지 않는다.
- 사용자 시나리오와 UX 개선안을 먼저 도출하고 다음 단계에서 UI를 재설계·구현한다.
- 넓은 데스크톱의 인용문 댓글은 홈 패널을 재사용하지 않고 인용문 왼쪽에 상단을 맞춘다. 모바일은 현재 방식을 유지한다.
- 데스크톱 왼쪽 홈·서재 패널에 접기·펼치기를 제공한다.
- 추가 선택 `2,1,1`: 댓글 공간 부족 시 홈 자동 접기, 홈은 기본 펼침·현재 접속 동안 상태 기억, 댓글은 인용문과 함께 스크롤.
- 책 전체 메모를 입력할 때 박스 둘레에 생기는 파란 선을 제거하는 방향으로 재설계한다.

아래 우선순위·철회·보류 판정은 Codex 제안이다. 승인 전 기능 정책으로 확정하지 않는다.

## 이전 제안의 문제

1. **문장이 보이는 것과 저장 상태가 보이는 것을 섞었다.** 사용자가 하려는 일은 방금 쓴 문장을 읽고 다음 문장을 쓰는 것이다.
2. **불편을 줄인다면서 표시와 선택을 늘렸다.** 검색 범위 선택기, 전용 미리보기, 상시 안내를 필요성 확인보다 앞서 제안했다.
3. **관찰한 불편과 가설을 같은 순위에 놓았다.** 새 문장 미노출·테마 목록 문제는 재현했지만 쪽수 유지·읽던 위치 복원의 필요성은 확인하지 않았다.
4. **결정 부담을 사용자에게 넘겼다.** 이전의 7개 결정 묶음은 철회한다. 해결할 문제에 꼭 필요한 선택만 관련 설계 단계에서 묻는다.

## 시나리오 재구성

실제 사용자 인터뷰 결과가 아니라 제품 기능과 관찰에 근거한 검증용 상황이다.

### S1. 책을 읽다가 문장을 남긴다

- **상황·목표:** 문장과 쪽수를 적고 독서로 돌아간다.
- **현재 근거:** 카드 외곽선, 바깥 전체 폭 구분선·그림자, 카드 내부 구분선이 겹친다.
- **개선 제안:** 문장·쪽수·입력 행동을 하나의 카드로 표현하고 중복 경계를 정리한다. 저장 상태와 상시 사용법 안내를 새로 붙이지 않는다. 기존 키보드·한글 조합 처리는 유지한다.
- **검증:** 긴 문장 붙여넣기, 쪽수 없는 기록, 줄바꿈, 한글 조합 중 Enter에서 입력 의도대로 작동하는지 확인한다.

### S2. 여러 문장을 이어 적는다

- **상황·목표:** 목록 중간을 보다가 문장을 추가하고, 방금 쓴 문장을 읽은 뒤 다음 문장을 적는다.
- **현재 근거:** 로컬에서 새 문장 추가 후 목록 높이는 3663px → 3772px가 됐지만 스크롤은 0px에 머물렀다. 입력란은 비워지고 포커스는 돌아왔다.
- **개선 제안:** 본인이 추가한 문장이 입력 카드 위에 보이게 이동한다. 문장 자체로 결과를 확인하게 하고 저장 배지·성공 알림·별도 확인 버튼은 추가하지 않는 방향이다. 쪽수 유지·자동 증가는 보류한다.
- **검증:** 목록 위·중간·아래, 긴 문장, 연속 추가, 추가 직후 책 전환에서 새 문장 노출과 다음 입력이 자연스럽게 이어지는지 확인한다.
- **남은 결정:** 자동 이동 시점·대상은 다음 단계에서 아래 3안 중 선택한다.

### S3. 글자 크기를 바꾸면서 편한 모양을 찾는다

- **상황·목표:** 읽던 본문이 작아 보여 크기·너비·서체를 바꾸고 같은 문장부터 계속 읽는다.
- **현재 근거:** 설정의 배경 흐림 효과가 실제 본문 변화를 가린다. 프로필에는 비어 있는 상태 안내 공간이 남는다.
- **개선 제안:** 조절하는 동안 실제 본문을 알아볼 수 있게 하고 빈 공간을 줄인다. 별도 예시·미리보기 화면·저장 상태 안내를 추가하지 않는다. 섹션 순서와 값의 범위를 바꾸기 전에 현재 구성 안에서 정리한다.
- **검증:** 패널을 여러 번 열고 닫지 않아도 변화가 보이는지, 닫은 뒤 읽던 내용이 유지되는지 확인한다.

### S4. 원하는 테마를 고르거나 선택을 취소한다

- **상황·목표:** 목록 끝의 테마를 선택하거나 취소하고 읽기로 돌아간다.
- **현재 근거:** 목록이 높이 제한 없이 아래로 펼쳐진다. 실제 브라우저에서 Escape 한 번에 목록과 설정이 함께 닫혔다. 기존 자동 테스트의 기대 동작과 다르다.
- **개선 제안:** 목록이 사용 가능한 화면 안에서 펼쳐지고 내부 스크롤로 끝까지 도달하게 한다. Escape는 목록부터, 다음 Escape는 설정을 닫는다. 모든 기존 테마는 유지한다.
- **검증:** 작은 창에서 마지막 옵션 선택, 취소, 두 단계 Escape, 포커스 복귀를 실제 브라우저로 확인한다.

### S5. 다른 구절을 참고하며 생각을 쓴다

- **상황·목표:** 문장을 읽으며 바로 옆에 댓글을 작성하고, 필요하면 왼쪽 서재에서 다른 책을 찾는다.
- **현재 근거:** 댓글을 열면 왼쪽 홈·서재가 댓글 패널로 바뀐다. 구절 ID 변경 시 작성·수정 초안 초기화 코드도 있으며, 초안 유실은 아직 격리 환경에서 재현하지 않았다.
- **사용자 확정 배치:** 넓은 데스크톱은 댓글을 대상 인용문 왼쪽에 두고 두 영역의 상단을 맞춘다. 댓글과 홈 패널은 별도 영역이다. 홈 패널은 접기·펼치기를 제공한다. 모바일 댓글 UI는 현재 방식을 유지한다.
- **추가 검토:** 초안 보호 해법은 아직 미승인이다. 댓글 전환 시 유실을 먼저 재현하고 필요하면 보존 범위를 선택한다. 새 초안 관리함·저장 배지는 추가하지 않는다.
- **다음 단계 화면:** 댓글 닫힘, A 댓글 열림, 홈 펼침/접힘, B 댓글로 전환, 여러 댓글·긴 댓글, 오른쪽 전체 메모와 동시 표시, 모바일 현재 화면.
- **검증:** 댓글을 열어도 홈 패널이 다른 내용으로 바뀌지 않아야 한다. 댓글과 대상 인용문의 상단 정렬, 본문 가림·영역 겹침, 홈 접기/펼치기 후 재정렬을 확인한다. A 작성 → B → A, Escape, 모바일 유지도 함께 확인한다. 화면 폭 기준과 긴 댓글·스크롤 처리는 다음 단계에서 선택한다.

### S6. 기억나는 단어로 예전 문장을 찾는다

- **상황·목표:** 다른 책을 보다가 검색으로 원하는 문장을 찾고 주변 내용을 읽는다.
- **현재 근거:** 코드에서는 현재 책·저자·폴더 필터 적용 후 검색한다. 검색 범위를 오해할 가능성은 가설이며 실제 사용자 불편으로 재현하지 않았다.
- **개선 제안:** 현재 책에 없고 다른 책에만 있는 문장을 찾는 과제를 먼저 수행한다. 실패가 확인되면 문구나 기본 동작부터 검토한다. 범위 메뉴·새 검색 화면은 우선 만들지 않는다.
- **검증:** 원하는 문장 도달 여부, 범위 오해 여부, 검색 결과에서 책으로 이어지는 과정을 기록한다.

### S7. 책 전체에 대한 생각을 남긴다

- **상황·목표:** 책에 관한 질문을 적고 생각과 독서를 이어간다.
- **현재 근거:** 기존 책 메모에 자동 저장·초안 보존 기능이 있으며 로컬에서 저장 경로가 작동했다.
- **추가 관찰:** 실제 운영 화면의 메모 입력칸을 클릭하면 박스 둘레에 파란 선이 생긴다. 계산된 스타일은 outline-style: auto, outline-width: 1px, outline-color: rgb(153, 200, 255)다. border는 0px이고 box-shadow의 확장 크기는 0px이므로 브라우저 기본 포커스 외곽선이 원인이다.
- **사용자 확정:** 전체 메모 입력 박스의 파란 외곽선을 제거하는 방향으로 재설계한다.
- **개선 제안:** 저장 상태 확인을 사용자 과제로 만들지 않는다. 대상 책과 내용 보존을 확인하며, 구절 메모·책 메모 통합이나 저장 방식 변경은 제안하지 않는다. 키보드 이용자가 현재 입력 위치를 알아볼 수 있는지도 별도 검증한다.
- **검증:** 마우스로 클릭해 입력하는 동안 파란 박스가 나타나지 않는지, 키보드로 진입·이동할 때 입력 위치를 알아볼 수 있는지 확인한다. 입력 직후 책 이동·패널 접기의 내용 보존도 확인한다.

### S8. 모바일 키보드로 기록한다

- **상황·목표:** 휴대전화에서 문장·쪽수를 입력하고 바로 다음 행동으로 넘어간다.
- **현재 근거:** 모바일 레이아웃은 있으나 실제 소프트웨어 키보드 검증은 미완료다.
- **개선 제안:** 입력창·입력 버튼·새 문장이 가려지는지 먼저 확인한다. 문제 재현 전에 별도 모바일 입력 모드나 화면을 추가하지 않는다.
- **검증:** 실제 키보드가 열린 상태에서 문장 → 페이지 → 입력, 긴 문장, 메모 시트, 화면 회전. 375px 캡처만으로 통과 처리하지 않는다.

## 다음 UI 설계에 넘길 우선 범위 — 제안

1. **입력:** 겹치는 경계 정리 → 방금 입력한 문장 노출 → 다음 입력으로 연결.
2. **설정:** 실제 본문 변화 확인 → 목록을 화면 안에서 선택 → 자연스럽게 닫기.
3. **댓글·홈 패널:** 사용자 확정 배치에 따라 넓은 데스크톱에서 홈 패널과 댓글을 분리하고, 홈 접기·펼치기와 인용문 왼쪽 상단 정렬을 설계. 모바일은 유지.
4. **전체 메모:** 입력 박스의 파란 외곽선을 제거하고 키보드 입력 위치 식별을 검증. 초안 보호는 유실 재현 후 별도 판단.

검색 범위 선택기, 쪽수 자동 처리, 읽던 위치 복원, 고정 제목, 별도 미리보기는 당장 만들 기능 목록에서 뺀다. 필요한 근거가 생긴 것만 다시 검토한다.

### 다음 단계의 첫 동작 결정 후보: 새 문장 이동

| 안 | 사용자 경험 | 검토 |
|---|---|---|
| ① 본인의 새 문장이 목록에 추가되면 즉시 보이게 이동 | 바로 확인하고 다음 입력으로 이어감 | **추천** |
| ② 서버 저장 성공 후 이동 | 연결이 느리면 뒤늦게 화면이 움직임 | 연속 입력을 방해할 가능성 |
| ③ 현재 위치 유지 + 이동 버튼 | 확인하려면 버튼을 눌러야 함 | 현재 불편에 조작을 더함 |

추천안은 아직 선택되지 않았다. 기존 질문이 자동 승인된 것으로 처리하지 않는다. 다른 정책·구조·로직 변경도 필요가 확인된 시점에만 3안으로 제시한다.

## 결정 감사

- 사용자 결정: 저장 상태 표시 불필요. 시나리오·개선안부터 재검토하고 UI·구현은 다음 단계.
- 사용자 추가 결정: 넓은 데스크톱의 댓글은 인용문 왼쪽 상단 정렬, 홈 패널 재사용 금지, 홈 접기·펼치기, 모바일 현재 방식 유지, 전체 메모 파란 외곽선 제거.
- Codex 결정: 저장 상태 강화·별도 미리보기·7개 결정 묶음을 철회하고 재현된 입력·설정 문제로 우선 범위를 축소.
- 기존 유지: 앱 코드·저장 처리·데이터 보호·기존 Figma. 기존 Readwise 비교 기준도 임의 폐기하지 않음.
- 미검증: 사용자 인터뷰, 검색 불편, 초안 유실 재현, 서버 실패·재접속, 실제 모바일 키보드.
- 남은 사용자 결정: 다음 단계의 새 문장 이동 방식. 실패 시 안내 방식은 기존 복구 정책과 구분하며 이번에 새로 확정하지 않음.
- 남은 사용자 결정: 데스크톱 적용 폭·공간 부족 시 처리, 홈 초기 상태·기억 범위, 긴 댓글·스크롤 중 정렬 방식. 관련 설계 시 각각 3안과 추천을 제시하며 임의 확정하지 않음.
- 위 초기 상태·기억 범위·공동 스크롤·공간 부족 시 홈 접기는 `2,1,1`로 확정됐다. 현재 결과와 나머지 경계 조건은 [R2 재설계 기록](./figma-redesign-r2-2026-09-08.md)을 따른다.
