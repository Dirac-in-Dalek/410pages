우선 조치 목록

P1 · 필수 선행 조건
챕터 단계 마이그레이션을 코드 배포 전에 적용

확인 결과
운영 Supabase의 410pages 프로젝트에서 information_schema.columns와 마이그레이션 이력을 읽기 전용으로 조회했다. public.chapter_blocks에 depth 열이 없고, 새 마이그레이션도 이력에 없다.
영향
하위 단계 저장과 제목 편집의 단계 변경이 실패한다. 드래그는 최상위도 depth: 0을 보내므로 일반 챕터 드래그까지 실패한다. 기존 데이터가 삭제된다는 뜻은 아니다.
권고
배포 대상과 적용 이력을 확인한 뒤 준비된 단계 추가 마이그레이션을 먼저 적용하고, 기존 챕터 기본값과 실제 계정의 단계 저장을 확인한다. 그 뒤 운영 환경변수로 앱을 빌드·배포한다.
근거
마이그레이션 SQL · 저장 API, 53–59행 · 적용 안내

P2 · 코드 수정 권고
키보드 단계 변경의 미리보기와 저장 결과를 일치시키기

재현
저장 단계가 A=0, B=0, C=2일 때 화면은 A=0, B=0, C=1로 보정된다. B 제목 맨 앞에서 Tab을 눌러 1단계로 바꾸면, 편집 중 C의 선은 A에 연결되지만 저장 직후 B로 바뀐다. React·jsdom의 독립 검사로 재현했다.
보이는 차이
편집 중                 저장 직후
A                       A
 ├ B                     ╰ B
 ╰ C                        ╰ C
원인
전체 저장 데이터를 사용한 예상 단계 계산은 드래그에만 적용되어 있다. 키보드 편집에서는 다른 항목의 기존 화면 단계가 남아 미리보기 연결선 계산에 사용된다.
권고
키보드 편집에도 전체 예상 단계 계산을 사용하고, 같은 계산을 쓰는 새 챕터 삽입 미리보기도 점검한다. 이번 리뷰에서는 수정하지 않았다.
근거
연결선 계산, 18행 · 드래그 전용 예상 단계, 270–271행

미결정·미검증

  • 새 챕터 추가·Tab의 기본 소속: 사용자가 교정한 “선택한 위치의 상위”를 중첩 예시로 확인하는 결정이 남아 있다. 위 연결선 결함과 별개의 문제다.
  • 자동 번호·하위 전체 접기·자동 목차와 인용문 배치의 남은 규칙은 챕터 Policy를 따른다.
  • 운영 DB 변경·배포·실제 계정 저장, 실기기 터치·한글 IME·Safari·PWA는 이번 검증에 포함하지 않았다.
  • 배포 플랫폼의 운영 환경변수는 조회하지 않았다. 로컬 검사용 빌드가 운영 배포 준비 완료를 뜻하지 않는다.

권장 진행 순서

  1. 키보드 편집 미리보기 결함을 수정하고 해당 재현 사례를 검사에 포함한다.
  2. 준비된 DB 마이그레이션을 먼저 적용하고 기존 행·단계 저장을 확인한다.
  3. 운영 환경변수로 빌드·배포한 뒤 실제 계정에서 저장·새로고침을 확인한다.
