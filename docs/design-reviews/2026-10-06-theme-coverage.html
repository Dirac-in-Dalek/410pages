  • 사전 조사에서는 수정 전 설정과 후보 CSS 각각 14개 테마 × 시스템 모드 2개를 검사했다. 총 56개 조건, 대표 스타일 8종의 실제 계산 색상·바탕색 448개를 기록했다.

원인
  1. features/settings/logic/preferencesDocument.ts는 앱의 선택 테마에 맞춰 루트의 .dark와 data-theme를 바꾼다.
  2. 수정 전 tailwind.config.js에는 darkMode가 없어 dark: 유틸리티가 시스템의 prefers-color-scheme를 따른다.
  3. 앱 바탕색은 선택 테마를, 오류 글씨는 시스템 모드를 따르면서 서로 맞지 않는 색 조합이 생긴다.
  4. 실제 사용자 탭에서도 앱 day / 앱 색상 체계 light / 시스템 다크가 동시에 확인됐다. 사용자 화면을 바꾸지 않고 검사 페이지에서 OS 모드를 재현했다.

Tailwind v3 공식 문서는 기본 시스템 기준과 .dark를 따르는 selector 방식을 구분한다. 설치된 버전은 3.4.19다.

같은 원인으로 고쳐지지 않는 부분

  • 고정 빨간 삭제 글씨: 일부 메뉴는 text-red-600을 고정하고 dark:로는 호버 바탕만 바꾼다. 어두운 테마에서 카드 바탕 기준 최소 3.313:1이다. 다크 모드 기준을 바꿔도 글씨색은 그대로라 별도 색상 수정이 필요하다.
  • 브랜드색 챕터 오류: index.css의 .chapter-hint[role="alert"]는 --accent를 쓴다. Terminal Green에서는 오류도 녹색, Bach 계열에서는 갈색·금색이 된다. 카드 바탕으로 검사한 Airbnb Light와 Shostakovich Dark는 텍스트 대비가 4.5:1 미만이었다. 실제 챕터 화면 바탕에서는 재확인이 필요하다.
  • 반증: 앱 전역 실패 알림은 어두운 바탕색까지 함께 바뀌어 현재도 최소 9.159:1로 읽힌다. dark:가 있다는 이유만으로 모든 표시가 읽히지 않는다고 판단하면 안 된다.

수정 범위 제안

사용자가 ① 공통 테마 판단 기준 통일을 선택해 적용했다. 아래는 당시 검토한 대안이다. 고정색 문제는 별도 선택 범위로 남아 있다.

선택지얻는 것남는 것 / 비용
① 공통 기준 통일 — 선택·적용 완료tailwind.config.js에 darkMode: 'selector' 한 항목을 추가. 기존 .dark 관리와 모든 dark: 사용처가 같은 기준을 따름. 새 테마도 등록부의 scheme에 따라 적용됨.고정 삭제색·브랜드색 오류의 의미 및 대비는 별도 점검.
② 공통 기준 통일 + 오류·성공 의미색 정리브랜드 강조색과 오류·성공색을 구분해 테마가 늘어도 상태의 의미를 유지.영향을 받는 여러 컴포넌트의 표현 선택과 전환이 추가로 필요.
③ 로그인 문구만 수정한 화면의 즉시 가독성 개선.다른 화면과 다음 컴포넌트에서 같은 원인이 남음. 추천하지 않음.

--accent로 오류 글씨를 일괄 치환하거나 테마별 하드코딩을 늘리는 방법은 추천하지 않는다. 기존 테마 등록부·공통 판단 기준을 재사용하는 것이 확장에 유리하다.
