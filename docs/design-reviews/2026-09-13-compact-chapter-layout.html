같은 행, 같은 시작선.
기존 구분선 하나.

관리 버튼은 제목과 같은 행에 두고, 원래 경계선을 눌러 챕터를 추가한다. 추가 전용 행과 중복 선을 없앴다.

YouTube 실제 답글을 펼쳐 부모·자식·손자·형제의 연결을 확인했다. 형제는 공통 부모의 세로선을 공유하고, 각 자식 앞에서 한 번만 부드럽게 휘어진다.

로컬 코드와 검증 결과다. 운영 DB 변경·앱 배포는 하지 않았다.

반영한 내용

  • 제목 옆 조작: 접기는 왼쪽, 수정·삭제는 오른쪽 같은 행이며 제목 자체를 끌어 이동한다. 중복된 점 6개 손잡이는 제거했다. 짧은 제목의 조작 행은 44px이며 긴 제목은 필요한 만큼 줄바꿈한다.
  • 읽기 열 통일: 책 제목·최상위 챕터·인용문이 같은 시작선. 하위 제목만 들여쓴다.
  • 기존 선 재사용: 경계선은 항목당 하나. 그 위의 클릭 영역은 추가 행 높이를 차지하지 않는다. 클릭한 뒤에만 입력 공간이 펼쳐지며 다른 구분선은 유지한다.
  • 부모와 형제: 1.1과 1.2는 1에서 갈라지고, 1.1.1은 1.1에서 갈라진다. 세로선은 부모마다 한 번만 그린다. 되돌아가는 꺾임·각진 꼬리·화살촉은 없다.
  • 여백 축소: 서재·책 목록의 상단과 제목 아래 여백을 줄였다. 빈 인용문 입력 영역은 72→52px로 줄이고 하단 고정과 입력에 따른 확장은 유지한다.

앞선 중간 구현의 역방향 꺾임과 중복 선은 잘못된 처리였다. 행 하나의 수치만 보지 않고 실제 본문과 여러 계층이 있는 전체 화면으로 다시 검증했다.

실제 앱 화면

모의 데이터·직접 작성한 제목 예시이며 번호를 자동으로 붙인 화면이 아니다.

검증

  • 68개 파일 / 476개 자동 테스트, 타입 검사, 빌드 통과.
  • 개발·빌드 Chromium의 1440px·375px에서 버튼/제목 첫 줄 중심, 제목/편집 입력 시작선, 책 제목/최상위 챕터/본문의 시작선 일치와 가로 넘침 없음을 확인.
  • 추가 전용 행 높이 0, 기존 경계선 유지, 맨 위·빈 책 추가 입력의 겹침 없음 확인.
  • 형제는 공통 부모 세로선 하나, 손자는 직접 부모에 연결됨을 검사.
  • 기존 같은 단계 추가·전체 접기·키보드 단계 변경·저장 재시도·드래그 표시선 드롭·새로고침도 함께 검사.

저장 검증은 격리된 모의 API다. 사용자 책의 위치·내용을 임의로 바꾸지 않았다. 실기기 터치·Safari·PWA는 미검증이다.

결정 감사

사용자 결정
A안 기반 같은 행 조작, 여백 축소, 기존 선 클릭으로 추가, YouTube처럼 부모·자식과 형제 연결.
Codex 결정
접기는 왼쪽, 관리 조작은 오른쪽으로 배치했다. 구분선 클릭 영역과 편집 시 공간을 분리했다. 실제 버튼 중심을 기준으로 부모 세로선 하나와 자식별 곡선을 계산한다. 선이 본문 글자와 겹치는 부분은 그리지 않는다. 구체적인 여백·곡률·선 굵기·반응형 들여쓰기 값은 구현 판단이다.
기존 동작 유지
제목 그대로 표시, 같은 단계 기본 추가, 키 적용 문맥, 하위 전체 접기, 제목만 드래그, 인용문 위치, 하단 고정 입력과 실패 복구.
미검증 사항
실기기·Safari·PWA, 실제 계정 저장. 큰 빌드 묶음 경고는 유지된다.
남은 사용자 결정
이번 정렬·여백·연결선에는 없음. 앱 배포는 사용자 확인 후 별도 결정한다.
