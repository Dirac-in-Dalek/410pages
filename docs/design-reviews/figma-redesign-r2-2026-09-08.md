# R2 Figma 재설계 — 댓글·홈·입력·전체 메모

## 결과

- [1600px 홈 펼침](https://www.figma.com/design/1dxeJesMUtei5Ug48hKsmb?node-id=26-42)
- [1600px 홈 접힘](https://www.figma.com/design/1dxeJesMUtei5Ug48hKsmb?node-id=29-62)
- [1280px 자동 접힘·긴 댓글](https://www.figma.com/design/1dxeJesMUtei5Ug48hKsmb?node-id=30-70)

사용자가 선택한 `2,1,1`을 반영한 화면 상태 예시다. 1600px 두 화면의 홈 접기·펼치기는 Figma 클릭 전환으로 연결했다. 실제 앱 구현이나 반응형 완성이 아니다.

## 사용자 결정

- 댓글 공간이 부족하면 홈 패널을 자동으로 접는다.
- 홈 패널은 기본 펼침이며 접힘 상태를 현재 접속 동안 기억한다.
- 댓글은 인용문 왼쪽에 상단을 맞추고 인용문과 함께 스크롤한다. 별도 댓글 스크롤이나 화면 고정은 하지 않는다.
- 모바일의 댓글 방식은 유지한다.
- 전체 메모의 파란 입력 외곽선을 없애고, 저장 상태 표시는 하지 않는다.

## Codex 제작 판단

- 예시 화면 크기 1600×900과 1280×900, 댓글 영역 256px, 댓글과 인용문 영역 사이 24px. 제품의 확정 반응형 기준은 아니다.
- 긴 댓글 때문에 다음 인용문이 내려가 큰 빈 공간이 생기지 않도록 댓글은 왼쪽 여백에서 이어지게 배치했다. 현재 하나의 구절 메모를 여는 기존 정책을 전제로 한다.
- 원본·R1을 보존하고 새 프레임에만 적용했다. 기존 색상 변수·문장 컴포넌트를 재사용했다.
- 카드 바깥·내부의 중복 선과 과한 강조를 제거했다. 본문과 입력 카드가 우선하고, 전체 메모 저장 버튼은 보조 행동의 색상으로 낮췄다.
- 기존 대체 서체 Noto Sans KR 및 문장 15.04px를 유지했다. Pretendard와 완전히 같지 않다.
- 댓글 문장은 실제 저장 데이터가 아닌 검증용 예시다.

## 검증

- 세 프레임에서 댓글 제목과 대상 인용문 본문의 상단 차이: 각각 0px.
- 댓글이 대상 인용문 왼쪽에 있으며 서로 같은 세로 스크롤 영역 안에 있음.
- 댓글 자체의 스크롤 설정은 없음.
- 입력 카드 바깥 컨테이너·내부 도구줄의 테두리 개수는 각각 0.
- 저장 상태 글자와 체크 아이콘은 표시하지 않음.
- 홈 접기·펼치기 Figma 전환의 대상 노드와 스크롤 초기화 안 함 설정을 읽어 확인함.
- 넓은 화면과 긴 댓글 화면을 스크린샷으로 확인함. 긴 댓글이 본문과 겹치거나 다음 문장을 밀어내지 않음.

## 미검증·후속 작업

- 실제 브라우저에서 Figma 프로토타입을 클릭·스크롤하는 검증은 하지 않았다. 연결 설정과 레이어·스크린샷을 확인했다.
- 실제 반응형 자동 접힘·접속 중 기억, 댓글 작성·저장, 포커스 외곽선 제거는 구현 단계에서 검증한다. 정적 Figma 화면에 파란 선이 없다는 사실로 앱 수정이 완료됐다고 판단하지 않는다.
- 모바일 UI는 변경하지 않았다. 이번에 모바일 재검증을 수행하지 않았다.
- 선택한 구절이 화면 아래에 있거나 댓글이 매우 긴 경우 스크롤 끝에서 댓글 전체에 도달할 수 있어야 한다. 현재 예시 외 데이터로 추가 확인이 필요하다.
- 설정 패널 재설계는 기존 UX 제안서의 후속 범위로 남는다.

- 홈을 접어도 댓글과 인용문 공간이 부족한 경우.
- 공간이 부족한 상태에서 사용자가 홈 펼치기를 누르는 경우.
