# 현재 페이지 UI 재리뷰 — 중요도가 먼저 보이는가

확인: 2026-09-08, 실제 [410pages](https://410pages.vercel.app/) 롱뷰 화면·설정 화면. 창 1087×716px. Figma 대체 서체 화면이 아닌 현재 운영 화면을 확인했다. 읽기 화면과 설정 화면의 스크린샷, DOM 치수를 근거로 한다.

## 결론

본문은 잘 읽히지만 보조 영역·반복 경계·프로필이 공간과 강조를 많이 차지한다. 읽기 화면에서는 인용문, 설정에서 읽기 모양을 조절할 때는 본문 변화가 우선해야 한다는 관점의 검토다. 사용 빈도는 측정하지 않았으므로 프로필 사용이 적다는 사실로 단정하지 않는다.

## 주요 발견

| 우선 | 현재 관찰 | 영향 | 재설계 방향 제안 |
|---|---|---|---|
| 1 | 왼쪽 232px, 오른쪽 메모 320px, 본문 535px. 본문은 전체 폭의 49.2%, 보조 영역 합은 50.8% | 이 창 크기에서는 글을 읽는 영역보다 보조 영역이 더 많은 폭을 차지한다 | 좁은 창에서 본문 폭을 우선하는 공간 배분을 검토. 접힘 기본값·폭·배치 변경은 아직 미승인 |
| 2 | 입력 카드 외곽선, 내부 가로선, 카드 바깥 전체 폭 가로선이 겹친다 | 하나의 입력 행동이 여러 구역으로 나뉘어 보이고 문장보다 경계가 눈에 걸린다 | 카드 자체의 구분으로 충분한지 확인하고 중복 경계를 제거하는 방향 |
| 3 | 본문 위에 돌아가기, 저자/책 경로, 큰 책 제목, 안내 문장이 연달아 보인다 | 첫 인용문에 도달하기 전에 같은 맥락과 안내를 반복해서 읽는다 | 책 제목을 중심으로 정리하고 반복 안내는 줄이는 방향. 돌아가기 기능은 보존 |
| 4 | 쪽수·날짜·메모 0이 매 문장마다 같은 줄에서 비슷한 무게로 보인다 | 출처로 필요한 쪽수와 덜 필요한 정보가 동등하게 취급된다 | 쪽수의 위치를 안정적으로 유지하고 날짜·빈 메모 수의 시각적 비중을 낮추는 방향. 메모 진입 동작을 숨기는 것으로 해결하지 않음 |
| 5 | 오른쪽 책 메모의 빨간 저장 버튼이 항상 강하게 보인다 | 읽고 있는 인용문과 무관한 보조 행동이 시선을 끈다 | 수동 저장 기능은 유지하되 주 행동처럼 강조하지 않는 방향. 상태 표시를 추가하지 않음 |
| 6 | 설정 첫 블록에서 프로필 사진·이름·사진 변경과 빈 공간이 큰 면적을 차지한다 | 글자 크기를 바꾸려는 상황에서 관련 없는 영역부터 지나간다 | 기존 섹션 순서 안에서 프로필 면적·빈 공간을 줄이는 방향부터 검토. 순서 변경은 기존 Policy에 있으므로 별도 결정 필요 |
| 7 | 설정 뒤 본문이 흐려진다 | 읽기 모양 변경 결과를 확인하기 어렵다 | 현재 본문을 알아볼 수 있도록 가림·흐림을 줄이는 방향. 별도 미리보기 화면은 추가하지 않음 |

## 유지할 요소

- 인용문을 개별 카드로 감싸지 않은 평면 목록.
- 본문보다 보조 글자가 어둡게 표현되는 기본 대비 관계.
- 긴 문장의 줄 간격과 입력 카드의 명확한 위치.
- 현재 선택한 최근 책을 구별하는 표시. 색상 대비 문제는 별도 검증 대상으로 유지.

## 다음 설계의 검토 순서

입력 영역의 중복 경계 → 설정 프로필 여백·본문 가림 → 좁은 창의 본문 공간 → 제목 주변 중복 정보 → 반복 메타데이터·보조 버튼 강조.

이 순서는 Codex 제안이다. 화면 전체를 일괄 재배치하거나 새로운 모드·메뉴를 추가하자는 승인이 아니다. 주요 기능을 찾기 어렵게 만드는 방식의 단순화는 피한다.

## 결정 감사

- 사용자 결정: 중요한 것이 먼저 보여야 한다는 UI 기준에 동의하고 현재 페이지 재리뷰 요청. 저장 상태 표시 불필요. 구현은 다음 단계.
- Codex 결정: 현재 창의 공간·강조·반복 정보에 따른 발견 7개와 검토 순서. 모두 개선 제안.
- 기존 유지: 앱 코드, Figma, 기능·저장 정책. 검토 후 설정을 닫아 읽기 화면으로 복귀.
- 미검증: 다른 창 크기와 모바일, 시선 추적·사용 빈도, 제안 적용 후 사용자 성과.
- 남은 사용자 결정: 공간 배분·접힘 기본값·섹션 순서 등 구조 변경은 실제 재설계 전에 선택 필요.
