# 책 목차와 챕터 Policy

## 확정 정책

- 기능 이름은 `챕터`이다. 이름 변경만으로 별도 소속 저장 구조를 도입하지 않는다.
- 인용문 목록 맨 위에도 챕터를 추가할 수 있어야 한다.
- 챕터 아래에 하위 챕터를 둘 수 있어야 한다.
- 챕터는 책 본문형으로 표시한다. 장·절 제목의 크기와 제목 사이 여백으로 계층을 구분한다.
- 인용문·페이지·메모는 소속 챕터 제목의 시작선에 맞추고, 하위 단계에서는 함께 들여쓴다. 2026-09-13 오후 사용자의 1번 시안 선택으로 이전의 모든 인용문 공통 시작선 규칙을 대체한다.
- 챕터 제목과 인용문을 화면의 중심에 두고 제목 주변의 관리 버튼을 최소화한다. 저장 대상은 하단 입력창에서 확인한다.
- 책을 입력해 열면 외부에서 가져온 실제 목차가 자동으로 입력되어 있어야 한다.
- 챕터는 접고 펼칠 수 있어야 한다.
- 가져올 목차가 없으면 목차를 비워 두고, 사용자가 직접 챕터를 추가한다.
- 인용문 입력창은 화면 하단에 항상 고정한다. 챕터별로 입력창을 만들거나 이동시키지 않는다.
- 사용자가 챕터를 클릭하면 해당 챕터가 펼쳐지면서 인용문의 저장 대상으로 선택된다. 인용문은 하단 고정 입력창에서 작성해 선택한 챕터에 추가한다.
- 목차에 챕터 시작 페이지가 있으면, 인용문에 입력한 페이지를 기준으로 해당 챕터에 자동 배치한다.
- 클릭한 챕터와 입력한 페이지가 가리키는 챕터가 다르면 입력한 페이지를 우선한다.
- 입력한 페이지로 챕터를 찾을 수 없으면 선택한 챕터에 저장한다. 선택한 챕터도 없으면 미분류로 저장한다.
- 챕터는 목차 순서로 표시하고, 챕터 내부 인용문은 페이지 순서로 표시한다.
- 챕터는 처음에 모두 펼친다. 접힘 상태는 접속 중 유지한다.
- 인용문 저장 후에도 선택한 챕터를 유지한다.
- 기존 인용문·챕터는 새 챕터 구조에 따라 자동 재분류하며, 재분류를 되돌릴 수 있어야 한다.
- 같은 제목·저자라도 판본이 다르면 별도 책으로 관리한다.

- 챕터 추가 위치는 선으로 표시하고, 마우스를 올리면 추가 조작을 드러낸다. 맨 위에도 같은 표시 방식을 쓴다.
- 챕터 제목은 더블 클릭으로 수정할 수 있어야 한다.
- 챕터 드래그는 제목만 이동한다. 인용문·댓글 위치는 유지한다.

## 2026-09-11 사용자 확정 — 키보드로 단계 변경

- 챕터 제목 맨 앞에 커서가 있을 때만 단계 변경 키를 적용한다. 나머지 위치에서는 일반 입력키로 사용한다.
- `Tab` 또는 `Space`는 현재 챕터를 바로 위 챕터의 하위로 넣는다. 상위 챕터를 고르는 별도 조작은 요구하지 않는다.
- `Delete` 또는 `Backspace`는 현재 챕터를 한 단계 밖으로 꺼낸다.
- 하위 관계는 단계+순서로 저장한다. 바로 위 항목을 기준으로 관리하며 챕터를 옮기면 상하 관계도 새 순서에 맞춰 바뀐다.
- 하위 챕터에는 하위임을 알아볼 수 있는 표시를 둔다. 2026-09-11 사용자가 추가로 제시한 댓글 이미지처럼, 부모에서 내려온 선이 하위 항목 앞에서 둥글게 꺾여 연결되는 표현을 사용한다. 앞선 `ㄴ>` 예시를 특정 문자 요구로 고정하지 않는다.
- 사용자 예: `1장 → 2장 → 새 구분선`에서 새 구분선에 Tab을 누르면 `2.1` 위치가 되고, Backspace를 누르면 같은 상위 단계의 `3장` 위치가 된다.

## 2026-09-12 사용자 확정 — 드래그 위치 미리보기

- 드래그 중 놓을 위치의 들여쓰기와 상위 챕터 연결선을 미리 보여준다.
- 놓으면 미리 표시한 위치와 단계에 맞게 소속이 바뀐다. 제목 내용은 유지한다.
- 단계+순서 저장을 계속 사용한다. 드래그는 제목만 옮기며 인용문·댓글 위치는 유지한다.
- 근거: 드래그 결과 설명 후 사용자가 `keep`의 뜻을 `계속`으로 확인하고 구현을 이어가도록 요청했다.

## 2026-09-12 사용자 확정 — 추가 위치·이름·접기

- 구분선에서 챕터 추가를 누르면 해당 위치의 챕터와 같은 단계의 다음 형제로 추가한다. 예: 2장 아래 2.1 바로 밑에서 추가하면 2.2 위치다. 기본으로 2.1.1 아래에 넣지 않으며 별도 Tab 조작이 필요하지 않다.
- `2.2` 등은 소속·순서를 설명하는 예시다. 앱은 챕터 번호를 생성하거나 제목 앞에 별도로 붙이지 않는다. 사용자가 직접 작성한 챕터 제목을 그대로 표시한다.
- 상위 챕터를 접으면 모든 하위 챕터와 해당 인용문을 함께 숨긴다. 같은 단계 또는 더 위 단계의 다음 챕터부터는 표시한다. 앞선 '다음 챕터 직전까지 접기' 범위를 대체한다.
- 제목 맨 앞에서 별도로 누르는 Tab/Space 하위 이동과 Delete/Backspace 한 단계 밖으로 이동은 유지한다. 새 챕터 추가의 기본 소속과 단계 변경 키를 구분한다.

## 2026-09-13 사용자 확정 — 정렬과 기존 구분선 재사용

- 정렬 A안을 바탕으로 제목과 이동·수정·삭제 조작을 같은 행에 둔다. 관리 버튼 때문에 두 번째 행을 만들지 않는다.
- 페이지 전반의 불필요한 여백을 줄인다. 장·절 제목과 인용문의 읽기 흐름을 기준으로 배치를 확인한다.
- 챕터 추가 전용 행이나 두 번째 가로선을 만들지 않는다. 기존 항목 경계선 자체를 클릭해 추가하고, 클릭한 뒤에만 제목 입력 공간을 펼친다.
- YouTube 중첩 댓글처럼 부모에서 자식으로 부드러운 곡선 하나씩 연결한다. 왼쪽으로 되돌아가거나 불필요한 각진 경로를 만들지 않는다.
- 같은 단계의 형제는 같은 들여쓰기에 놓고 공통 부모에서 각각 갈라진다. 1.2는 1과 연결하고, 1.1.1은 1.1과 연결한다. 번호는 관계를 설명하는 예시이며 자동으로 붙이지 않는다.

## 2026-09-13 사용자 확정 — 중복 손잡이 제거

- 별도 점 6개 드래그 손잡이를 제거하고 챕터 제목 자체의 드래그를 유지한다.
- 키보드 이동은 제목에 초점을 두고 Alt+위/아래로 사용할 수 있게 유지한다.

## 2026-09-13 사용자 확정 — 인용문 이동과 조작 표시

- 인용문을 다른 하위 챕터 아래로 드래그하면 그 하위 챕터 안으로 옮길 수 있어야 한다.
- 인용문에만 호버 시 이동 손잡이를 표시한다. 기존 본문 글자 선택·강조는 유지한다. 챕터는 별도 손잡이 없이 제목을 드래그하는 방식을 유지한다.
- 챕터 수정·삭제 버튼은 항상 표시하지 않고 호버 시 표시한다.

## 남은 사용자 결정

- 별도 챕터 소속 필드를 도입하는 구조 확장안은 철회한 상태를 유지한다. 단계+순서 저장과 위 추가·키·접기 동작은 확정했다.
- 페이지가 없거나 같은 인용문 사이의 세부 정렬 순서.
- 챕터 시작 페이지의 표시·수정 방식과 출처에 페이지 정보가 없는 경우의 처리.
- 시작 페이지가 일부만 있거나 상위·하위 챕터의 페이지 범위가 겹치는 경우의 자동 배치 규칙. 해당 챕터를 찾지 못한 경우의 저장 위치는 위 확정 정책을 따른다.
- 목차 조회 오류의 표시·재시도 방식과 이미 입력한 목차가 있는 책의 재조회 방식.

## 현재 구현 상태

- 2026-09-12 후속: 구분선의 앞 챕터와 같은 단계에서 새 제목 편집을 시작한다. 인용문 사이 구분선도 그 위치의 앞 챕터 단계를 사용한다. 맨 위는 최상위로 시작한다.
- 키보드 편집·새 챕터 추가·드래그의 미리보기 모두 임시 변경을 전체 저장 단계에 반영해 계산한다. 취소하면 원래 표시로 돌아간다. 저장 단계와 미리보기 표시 단계는 분리한다.
- 접힌 챕터 뒤 구분선은 숨겨진 전체 구간 뒤를 가리킨다. 추가·드래그·키보드 이동 시 숨겨진 내용 중간에 넣지 않는다. 다시 펼치면 개별 하위 챕터의 기존 접힘 선택은 유지한다.

- 2026-09-12: 드래그의 위아래 위치로 순서, 좌우 이동량으로 단계를 미리 표시한다. 상위 챕터 이름과 연결선을 보여주고, 순서·단계를 한 번의 요청으로 저장한다. 실패 시 기존 상태를 유지한다. 좌우 한 단계의 이동 간격은 기존 들여쓰기 1rem에 맞춘 구현 세부다.
- 드래그로 옮기기 전·후의 전체 저장 단계를 같은 계산에 사용해 미리보기 연결선과 저장 후 연결선을 일치시킨다. Alt+위/아래 순서 이동과 제목 맨 앞의 기존 키 동작은 유지한다.

- 본문형 챕터 표시, 맨 위·빈 책·문장 사이 추가, 제목 수정·제목만 이동, 하위 챕터·인용문 전체 접기를 제공한다.
- 2026-09-11: 하위 단계 저장 API, 제목 맨 앞의 단계 변경 키, 둥근 연결선을 앱 코드에 연결했다. 제목과 단계는 기존 제목 저장 경로에서 함께 저장하며, 실패하면 편집 값을 유지한다.
- 단계 저장용 마이그레이션 `20260912001242_add_chapter_depth.sql`을 2026-09-12 사용자 승인으로 운영 DB에 적용했다. 기존 챕터 34개의 기존 필드 값과 순서를 보존했고 모두 기본값 0으로 시작함을 확인했다. NOT NULL·음수 금지 제약과 RLS 활성화를 확인했다. 앱 배포는 사용자가 확인한 뒤 결정하기로 하여 실행하지 않았다.
- 실제 목차의 챕터 변환·선택한 챕터에 인용문 입력·페이지 자동 배치는 여전히 별도 작업이다. 번호는 자동 생성하지 않으며 하위 전체 접기는 위 후속 결정으로 확정했다.
- 2026-09-10 사용자는 다른 리뷰 추천안의 일괄 적용과 별개로 챕터 세부 배치 규칙은 따로 선택하기로 했다.

## 변경 이력

- 2026-09-08: 사용자 결정만 기록했다. 이 문서 추가로 앱 동작은 변경하지 않았다.
- 2026-09-08 첫 구현: 목록 맨 위·빈 책의 첫 구분선 추가와 기존 구분선의 본문형 제목 표시를 적용했다. 구분선 계층·소속 저장·접기·자동 목차·페이지 자동 배치는 아직 구현 전이다. 운영 DB와 배포에는 변경하지 않았다.
- 2026-09-08 추가 결정: 사용자가 세 질문에 모두 추천안을 선택했다. 페이지 판별 실패 시 선택 구분선 또는 미분류 저장, 목차·페이지 순서, 초기 펼침·접속 중 접힘 유지·저장 후 선택 유지를 확정했다. 이번 문서 갱신은 앱 구현 완료를 뜻하지 않는다.

- 2026-09-08 용어 수정: 사용자가 `구분선`이라고 정정했다. 화면 문구를 통일하며 기존 타입·DB 필드와 저장 동작은 유지한다. 앞선 하위 구분선·접기·페이지 배치 요구를 취소한 것으로 간주하지 않는다.
- 2026-09-08 접기 구현: 사용자가 다음 구분선 직전까지 숨기는 1안을 선택했다. 구분선 옆 버튼으로 해당 구간을 접고 펼친다. 접힘 상태는 로그인된 앱 화면에서 유지하며 책을 나갔다 돌아와도 보존한다. 새 접속에서는 모두 펼친다. 목차 자동 변환·페이지 배치·하단 입력 대상 선택은 이번 접기 구현에 포함되지 않았다.

- 2026-09-08 최신 용어 결정: 사용자가 `구분선` 대신 `챕터`로 되돌리도록 요청했다. 화면·접근성 이름·오류 안내를 챕터로 통일했다. 이번 변경은 용어만 변경하며 접기·저장 동작을 바꾸지 않는다.

- 2026-09-11 추가 결정: 사용자가 단계+순서 저장을 선택했다. 화면 이동 뒤 상하 관계가 새 순서에 따라 계산된다. 키·연결선의 구현 및 검증 결과는 [챕터 구현 결과](../design-reviews/2026-09-11-chapter-keyboard-result.html)에 구분한다.
