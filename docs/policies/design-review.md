# 화면 디자인 평가 Policy

## 현재 작업 단계 — 2026-09-08 사용자 지시

- 핵심 사용 흐름 전체의 사용자 시나리오를 만들고 UX 개선안을 도출한다.
- UI 재설계와 구현은 다음 단계에서 해당 개선안을 바탕으로 진행한다.
- 개선안은 승인 전 확정 기능 정책으로 기록하지 않는다.
- 저장 상태는 보여줄 필요가 없다. 이번 UX 개선안에서 저장 중·저장됨 표시를 사용자 경험의 목표로 삼지 않는다.
- UI는 중요한 것이 먼저 보이도록 글자 크기·색·여백·배치로 중요도를 표현한다. 구분선·테두리는 영역 구분에 필요한 곳에만 둔다.
- 현재 제안서는 [사용자 시나리오와 UX 개선안](../design-reviews/ux-scenarios-2026-09-08.md)이다.
- 사용자가 세부 배치 `2,1,1`을 선택하여 댓글·홈 패널의 Figma 재설계 단계로 진행했다. 앱 코드 구현은 아직 진행하지 않는다. 현재 산출물은 [R2 재설계 기록](../design-reviews/figma-redesign-r2-2026-09-08.md)이다.
- 이후 사용자가 R2 구현을 지시하여 앱 코드 구현 단계로 진행했다. 진행 및 미결정 예외는 [R2 구현 기록](../design-reviews/r2-implementation-2026-09-08.md)에 구분한다.

## 확정 정책

- 사용자 선택: `① 화면 디자인` 완료 기준을 적용한다.
- 비교 기준 사이트는 [Readwise Reader](https://readwise.io/read/)다.
- 비교 항목은 가독성, 정보 구분, 공간 배분, 시각적 일관성의 4가지다.
- Codex 판정으로 4항목 모두 기준 사이트와 동등 이상이고, 그중 2항목 이상에서 우세하면 완료한다.
- 글자 잘림과 겹침이 없어야 한다.
- 같은 한국어 내용, 화면 크기, 테마, 스크롤 위치로 비교한다.
- 이름을 가린 A/B 화면으로 비교한다. 최종 판정까지 Codex가 맡고, 측정값과 차이를 기록한다. 사용자에게 비교 판정을 다시 요청하지 않는다.
- 개선 루프는 `기준 화면 고정 → 수정 → 동일 조건 비교 → 미달 항목만 재수정`이다.
- 3회 후에도 미달이면 완료 처리하지 않고 사용자와 수정 방향을 다시 선택한다.
- 실제 사용성 비교는 이번에 선택한 화면 디자인 완료 기준에 포함하지 않는다.
- 이 작업에서 매일 오전 10시(Asia/Seoul)에 Figma 디자인 개선·비교·판정 루프를 실행한다.
